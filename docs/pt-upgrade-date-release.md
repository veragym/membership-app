# PT 업그레이드 날짜 지정

## 변경 내용

- 업그레이드 모달에 날짜 선택을 추가하고 기존 `todayISO()`의 로컬 날짜를 기본값으로 사용한다.
- 선택 날짜를 신규 PT 등록의 `contract_date`, 수강권의 `contract_date`, 결제 기록의 `payment_date`, 응답의 `new_contract_date`에 함께 기록한다.
- 날짜를 받는 9개 인자 `pt_upgrade` 함수를 추가한다. 날짜가 없거나 무한대이면 거부한다.
- 기존 8개 인자 함수는 변경하지 않는다. 날짜 없는 기존 클라이언트는 기존 동작을 유지한다.
- 가중평균, 결제 계산, 잔여 횟수, 기존 트레이너 변경 범위(`CURRENT_DATE` 기준 당월), 감사 기록 시각은 기존 동작을 유지한다.
- 날짜 지정 함수가 없는 서버에서는 저장 실패를 안내하며, 오늘 날짜로 바꿔 재시도하지 않는다.
- 새 함수의 소유자와 실행 권한은 기존 함수에서 복사한다. 전달받은 원본의 본문 해시가 달라지면 마이그레이션 전체를 중단한다.

## 운영 적용 순서

1. 대상 프로젝트는 `lrzffwawpoidimlrbfxe`이다. SQL Editor에서 `db/202610270001_pt_upgrade_date.sql` 전체를 실행한다. 이 파일은 함수만 추가하며 기존 회원/계약을 업그레이드하거나 수정하지 않는다.
2. 결과의 `date_upgrade_ready`가 `true`인지 확인한다. 오류가 나면 웹 배포를 진행하지 않는다. 원본 변경 오류라면 최신 `pg_get_functiondef`를 먼저 다시 조회한다.
3. 필요하면 `db/202610270001_pt_upgrade_date_check.sql`로 인자·소유자·권한을 읽기 전용 확인한다.
4. 그 뒤에만 웹 변경을 원격 `main`에 푸시한다. GitHub Pages가 저장 함수를 사용할 수 있게 된 후 새 화면을 제공해야 한다.
5. 운영 사이트의 `js/tabs/pt.js?v=45`와 날짜 입력란을 확인한다. 실제 회원의 업그레이드는 운영자가 선택한 날짜·금액으로 직접 실행한다.

## 검증

`npm ci` 후 `npm test`로 실행한다. Node.js 20.19 이상, 22.13 이상 또는 24 이상이 필요하다.

- 실제 PT 탭과 모달 코드를 DOM에서 실행하는 화면 테스트 4개.
- PostgreSQL(PGlite)에서 전달받은 원본 함수와 새 마이그레이션을 실행하는 테스트 9개.
- 과거 날짜 전파, 기존 횟수/단가 유지, 신규 수강권 생성, 회원 미매칭, 기존 함수 호환, 날짜 필수, 저장 중 오류의 원자적 취소, 실행 권한, 원본 변경 감지, 재적용을 검증한다.

DB 테스트는 함수가 사용하는 최소 스키마에 합성 데이터를 넣어 검증한다. 운영 스키마의 모든 트리거·RLS·삭제 함수를 복제한 검증은 아니다. 운영 회원 데이터에 시험용 업그레이드를 실행하지 않는다.

## 적용 전 상태

로컬 구현과 검증만 완료했다. 현재 CLI 로그인에는 대상 프로젝트 권한이 없으므로 운영 SQL 적용은 운영자가 수행해야 한다. SQL 적용 확인 전에는 웹을 배포하지 않는다.

기존 미커밋 `js/tabs/promo.js`와 `crawler/__pycache__/`는 이 변경과 무관하므로 포함하지 않는다.
